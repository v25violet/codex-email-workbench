# 首次设置

触发例：`$codex-email-workbench 开始设置`。每次只推进一个小阶段，并在阶段末总结已确认内容和下一步；不要一条消息要求用户填写全部配置。

## 1. 依赖检查

先判断当前会话是否有 Gmail、Outlook 和插件管理能力：

- 两者都可用：询问本次使用 Gmail 还是 Outlook。
- 只有一个可用：直接选择该分支，并说明选择依据。
- 都未连接：通过当前 Codex 的插件管理能力引导用户连接；连接由用户本人完成，Skill 不获取密码、token 或 Cookie。连接前可继续校验本地模板，但不执行邮箱动作。

不要把“推荐插件列表”当成已安装或已连接。只有实际能力检查成功后才说可访问。

## 2. 只读验证

连接后只做一次窄范围只读搜索，并列出连接器返回的可访问邮箱、共享邮箱或委派邮箱。此阶段不得发送、创建草稿、归档、移动、删除或改标签。

若用户期待的邮箱不在列表，停止并说明账号或权限不匹配。Gmail 链接中的 `/u/0/`、`/u/1/` 只是浏览器槽位，不能用来选择插件账号。Outlook 共享/委派邮箱必须记录准确的邮箱所有者标识。

## 3. 分步确认偏好

按以下顺序逐步确认，每次只问尚未确认的一小组：

1. 默认发件邮箱，以及共享/委派邮箱的所有者标识；
2. 时区和允许发送时段；
3. 显示名、签名和语言；
4. 用户自定义的发送上限（可留空；留空时不设置 Skill 固定上限，由连接器感知的自适应限速负责）；
5. 只建草稿，还是每批人工批准后发送（默认只建草稿）；
6. 单人本地 CSV，还是团队共享 Google Sheet/Excel。

把结果写入安装者自己的工作目录或表格，不改 Skill 包内的模板和参考文档。

## 4. 安全摘要

展示发件邮箱、签名、时区、限额和审批模式，请用户确认。默认开启回信、拒绝、退订和硬退信停发；自动回复默认暂停并等待人工确认。明确提示：已读回执、打开信号或浏览器显示状态不能触发核心状态变化。

## 5. 自测与结束

生成一封发给用户本人邮箱的测试邮件，先展示最终收件人、主题和正文。只有用户明确批准最终正文后才发送；否则只创建草稿，并明确“已创建草稿，未发送”。自测完成后给出这 5 条常用指令：

- `导入并校验这份联系人 CSV`
- `根据这个 brief 生成 5 封样本`
- `检查新回信并更新台账`
- `列出今天到期的 follow-up 候选`
- `生成今天的外联日报`

若连接器只支持草稿，整个设置流程仍可完成，但发送能力标记为不可用，不得模拟成功。
